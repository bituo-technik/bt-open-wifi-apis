# Modbus TCP

> 状态：初版 | 适用：所有 SPM / SDM Open Wi-Fi 分支（Modbus TCP over TLS 仅 Basic+ 与 Pro）| 依据固件源码 SXM_EW_C3 `5.1.16`、SDMV2 `1.2.12` / `3.1.19`；寄存器表与 Gitbook「Modbus TCP Map - ESP32-8685」一致

Modbus TCP 是 PLC、工业网关、EMS 读取电表数据最常用的方式。设备是 **Modbus TCP 服务端（从站）**，端口 **502**：由你来轮询，从固定寄存器读取电参量，设备不会主动推送。

## 1. 简介

| 项目 | 说明 |
|------|------|
| 端口 | `502` |
| Unit ID（从站地址） | 固件**不校验** Unit ID，原样回传；建议用 `1` |
| 功能码 | `0x03` 读保持寄存器，`0x04` 读输入寄存器（**数据相同**），`0x06` 写单个寄存器（仅控制寄存器） |
| 可读范围 | 寄存器 **978 ~ 1077**（共 100 个），见[第 4 节](#4-寄存器表) |
| 字序 | 32 位数据占两个寄存器，**高字在低地址（ABCD，大端）** |
| 开关 | 功能位 bit 15（`enablemodbustcp`，见[业务指令参考](../ble-common/ble-business-api.zh-CN.md)）；该位打开时服务才运行 |
| 并发连接数 | Basic / Lite：**2**，Basic+：**1**，Pro：**2**（与 TLS 槽位数相同，见[总览](../overview/open-wifi-overview.zh-CN.md#31-tls-连接数限制)） |
| 帧大小 | 单次接收最多 600 字节 |

用哪张寄存器表（单相 / 分相 / 三相）由产品型号决定，可读寄存器 984 的型号字符串（如 `SDM01_3PN`）或用 `model` 指令获取。

| 类型 | 产品（订货号） |
|------|----------------|
| 单相 | SPM01-D2EW、SPM01-D1EW、SPM01-U1EW |
| 分相 | SDM02-EW-12、SDM02-EW-20、SDM02-EW-10U |
| 三相 | SPM02-D2EW、SPM02-D1EW、SPM02-U1EW、SDM01-EWM-12、SDM01-EWM-20 |

## 2. 连接

### 2.1 明文连接

向 `<设备 IP>:502` 建立 TCP 连接，发送标准 Modbus TCP 帧（MBAP 头 + PDU）。设备 IP 可用 [mDNS 发现](../mdns/mdns-discovery.zh-CN.md)或路由器查看。

固件的连接行为：

- 连接可以保持并复用。空闲 **30 秒**设备会关闭连接（定制固件可能为 12 秒），轮询间隔比这更长的客户端需要重连。
- 所有槽位都被占用时，新连接要等到某个槽位释放才会被接受。
- 设备**一次只处理一个**请求。若接收缓冲里已有多个完整帧，只会应答**最新**的一个。请务必等到应答再发下一个请求。
- 长度字段与实际不符的帧会被**直接丢弃、没有应答**，客户端表现为超时。
- 建议两次请求间隔不小于 **150 ms**；电能数据通常没必要比约每秒一次更快地轮询。

> Gitbook 页面写的是设备只接受一个连接，并且每次读取后都会复位 socket，要求每次请求都重新连接。固件源码并非如此：连接会被保持。每次重连仍然可用，对简单客户端也是最稳妥的做法，所以这条建议保持兼容。差异已记入 CHANGELOG。

### 2.2 Modbus TCP over TLS

Basic+ 与 Pro 可以开启 Modbus TLS（用 `enabletls` / `enablemodbustcp` 打开功能位 bit 14 与 bit 15），此时 TLS 服务同样监听 **502**。TLS 槽位与 MQTTS、HTTPS、WSS 共用，优先级为 MQTTS > HTTPS > WSS > Modbus TLS，拿不到槽位的 Modbus 服务会**回退为明文**。详情和限制见[总览](../overview/open-wifi-overview.zh-CN.md#31-tls-连接数限制)。许多 PLC 和网关不支持 Modbus over TLS，这种情况请在可信网段内使用明文连接。

## 3. 功能码与异常

| 功能码 | 行为 |
|--------|------|
| `0x03` / `0x04` | 读取 978 ~ 1077 窗口内的寄存器；起始地址加数量必须落在窗口内 |
| `0x06` | 只有[第 5 节](#5-控制寄存器)的两个控制寄存器可写 |
| 其它 | 返回异常 `01` |

异常应答：

| 异常码 | 出现条件 |
|--------|----------|
| `01` 非法功能 | 功能码不是 03 / 04 / 06（包括 0x10 写多个寄存器） |
| `02` 非法数据地址 | 读取范围超出 978 ~ 1077，或写入的地址不是控制寄存器 |
| `03` 非法数据值 | 控制寄存器写入了约定值以外的数值 |
| `05` | 帧短于 12 字节（该码的非标准用法） |

## 4. 寄存器表

下表对应默认上报模式 `commonmode = 0`。设备切换到通用格式（`commonmode = 1`，见业务指令参考）后，Modbus 读取映射会换成另一套布局，下表**不再适用**。设备还有 `mda` / `minvert` 指令（SXM 与 SDMV2 固件），可为定制集成重映射寄存器地址或交换字节，本文不涉及；`mda` 同时会把 `commonmode` 设回 0 并打开 Modbus TCP。出厂布局即下表。

### 4.1 产品识别（基地址 978）

所有型号相同。字符串为 ASCII，每个寄存器放两个字符，**第一个字符在高字节**，不足的位置为 `0`。

|-------------|-------------|------|----------|------|------|
| 978 | `0x03D2` | MAC 地址 | 6 | 字符串（12 个字符） | `45705E597760` |
| 984 | `0x03D8` | 产品型号 | 5 | 字符串（10 个字符） | `SDM01_3PN` |

### 4.5 FLOAT32 的读取

所有测量值都是 **FLOAT32**，各占两个寄存器，**高字在前**。例如寄存器 `0x435C 0x0000` 即 `0x435C0000` = `220.0`。多数库里对应的设置是「Big Endian、字序 big / ABCD」。如果读出的数值明显不对（例如 `1.6e-41` 或特别大），说明工具用了字交换顺序（CDAB），请切换设置。

- 单位：功率为 **kW** / kVAR / kVA，电能为 **kWh**，电压 V，电流 A。与[遥测数据格式](../reference/telemetry-payload.zh-CN.md)中的 JSON 单位一致；固件直接拷贝电表芯片的寄存器，不做换算。
- 表中没有列出的地址（例如分相表的 1004）虽然在窗口内，但没有定义含义，请不要使用。

## 5. 控制寄存器

用功能码 `0x06` 写入。这些寄存器在读取窗口**之外**，**不可读**。

| 地址（DEC） | 地址（HEX） | 功能 | 写入值 |
|-------------|-------------|------|--------|
| 10001 | `0x2711` | 电能清零 | `0x51AA`（20906） |
| 10002 | `0x2712` | 定位：LED 闪烁 | `0x5055`（20565） |

- 值不对返回异常 `03`，地址不对返回 `02`。
- 定位会让 LED 闪烁（Gitbook 页面写的是约 15 秒），方便在密集的配电箱里找到对应的电表；效果与 `location` 指令相同。
- **电能清零不可恢复**，效果与 `zero` 指令相同。

> Gitbook 页面把定位寄存器写成 **10000**（`0x2710`）。固件源码里 Wi-Fi 模块通过 Modbus TCP 并不处理 10000：定位在 **10002**（`0x2712`）；10000 是表侧 MCU 上同一功能的地址，页面可能由此而来。10001 的清零在两处一致。本文以源码为准，请在真机上确认，差异已记入 CHANGELOG。

## 6. 示例

### 6.1 `mbpoll`

```text
# 读取三相总有功功率（1044，一个 FLOAT32 = 2 个寄存器），字序 ABCD
mbpoll -m tcp -a 1 -0 -B -t 3:float -r 1044 -c 1 192.168.1.50
```

`-0` 让地址从 0 开始（否则 `mbpoll` 从 1 数，要写 `-r 1045`），`-B` 选择大端字序。可以拿同一时刻 HTTP `/data` 的值对照，确认设置没错。

### 6.2 原生 Python

工具 [`tools/lan/modbus_poll.py`](../../tools/lan/README.md) 不依赖第三方库，并且会解析识别信息区。核心代码如下：

```python
import socket, struct

def read_regs(sock, start, count, unit=1, fc=3, tid=1):
    pdu = struct.pack(">BHH", fc, start, count)
    sock.sendall(struct.pack(">HHHB", tid, 0, len(pdu) + 1, unit) + pdu)
    head = sock.recv(7)                                  # MBAP: tid, pid, length, unit
    body = b""
    while len(body) < struct.unpack(">H", head[4:6])[0] - 1:
        body += sock.recv(256)
    if body[0] & 0x80:
        raise RuntimeError("Modbus exception %d" % body[1])
    return body[2:2 + body[1]]

s = socket.create_connection(("192.168.1.50", 502), timeout=3)
raw = read_regs(s, 1044, 2)
print(struct.unpack(">f", raw)[0], "kW")
```

## 7. 常见问题

| 现象 | 可能原因 |
|------|----------|
| 连接被拒绝 / 超时 | 功能位 bit 15 没开（`getFunctionMap`）、设备与你不在同一网段，或连接槽位都被占用 |
| 能连上但没有应答 | 帧长度不对，或没等应答就连续发了多个请求；错误帧会被静默丢弃 |
| 异常 02 | 范围超出 978 ~ 1077（例如一次读到 1078 以上） |
| 异常 01 | 功能码不是 03 / 04 / 06 |
| 浮点数很奇怪 | 字序不对（应为 ABCD），或地址差了 1（有些工具从 1 数起） |
| 信号强度是正数 | 它是绝对值，见[第 4.1 节](#41-产品识别基地址-978) |
| 约 30 秒后断开 | 空闲超时；请缩短轮询间隔或重连 |
| 502 上 TLS 握手失败 | 设备没拿到 TLS 槽位（已回退为明文），或客户端不接受设备证书；见[总览](../overview/open-wifi-overview.zh-CN.md#31-tls-连接数限制) |
